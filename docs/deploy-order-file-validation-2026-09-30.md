# Установка защиты от заказов без файлов — 30.09.2026

Исправление состоит из клиента и API. Клиент показывает причину блокировки и сохраняет введённые данные; API отклоняет пустой список файлов даже при прямом запросе. На рабочий хостинг это обновление ещё не установлено.

## Готовые файлы

- [metalworks-client-dist.zip](https://github.com/manucharyansos/metalworks-client/actions/runs/36771873790/artifacts/11124287103) — готовая сборка для `/work/`, с адресом рабочего API. Это артефакт успешного Client Security CI, построенный из клиентского коммита `04b87ac1bb7b004e44dd70985e1e55b2e5cc3641`.
- [metalworks-empty-order-api.patch](https://github.com/manucharyansos/metalworks-server/blob/451802e4b7953873df081c2ae34baf4dce1811d5/docs/releases/metalworks-empty-order-api.patch) — патч только для `app/Http/Controllers/Api/Engineer/EngineerController.php`. Он рассчитан на исходный серверный коммит `4c6bee69a0f79d7de11a23be9939cde5a11869c7`. Полное серверное изменение и тесты доступны в [PR #8](https://github.com/manucharyansos/metalworks-server/pull/8).

## Установка

1. Сохраните резервную копию текущего каталога `work/` и серверного `app/Http/Controllers/Api/Engineer/EngineerController.php`.
2. Распакуйте содержимое клиентского артефакта в существующий `work/`. Сохраните действующую конфигурацию хостинга и его `.htaccess`.
3. Скачайте серверный патч через Download raw на его странице. В корне серверного проекта выполните:

```sh
git apply --check /path/to/metalworks-empty-order-api.patch
git apply /path/to/metalworks-empty-order-api.patch
php artisan optimize:clear
```

Если проверка патча сообщает о несовпадении, перенесите изменения контроллера из PR #8 с учётом актуального серверного кода. Миграции и новые зависимости не нужны. Клиентское обновление без серверного патча оставляет возможность создать пустой заказ через API.

## Проверка после установки

- Для пустого подгруппового набора форма показывает сообщение и блокирует создание. Прямой запрос к API получает HTTP 422 без записи заказа.
- После выбора заполненной подгруппы доступны оба прежних режима: все её файлы (`link_existing_files: false`) и выбранные файлы (`true`) с количеством и назначенными операторами.
- Смена группы или подгруппы очищает прежние выбранные файлы. Ошибка загрузки предлагает повторить чтение; клиент, дата и описание сохраняются.
- При редактировании без нового выбора имеющиеся файлы заказа сохраняются.

Проверено: 73 клиентских теста; ESLint изменённых исходников; сборки на Node 20 и Node 24; 13 новых серверных HTTP-тестов с 121 проверкой, а также прежние тесты безопасности, менеджера и профиля. Серверные тесты используют отдельную SQLite-базу в памяти и подставную отправку почты.

В QA-группе 990 / подгруппе 01 добавлены и подтверждены после перезагрузки 19 новых файлов: по три в SW, DLD, DXF, IQS, PDF и четыре в INFO. SW/IQS — помеченные транспортные образцы, не производственные модели. В INFO подтверждены сохранённый многоязычный текст и загрузка PNG. Проверка мобильного интерфейса, воспроизведения аудио, отображения PDF/DXF и скачивания не завершена из-за отключения среды сеанса.

Для отката восстановите резервные копии клиента и контроллера, затем очистите кеш Laravel. Уже существующие заказы и вложения патч не удаляет.
